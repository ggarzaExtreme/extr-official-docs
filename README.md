# Extreme Docs Atlas

A map of Extreme Networks' public documentation: every document the two public sites list, where it lives,
what type it is, which releases it covers, and which hardware runs which software. A scan keeps it current,
and a profile turns any part of it into a folder of downloaded documents that stays up to date.

**Start here: [the explorer](https://ggarzaextreme.github.io/extr-official-docs/).** One page, no install.
It's also `index.html` in a clone, which opens in any browser. It has five tabs:

- **Dashboard**: the catalog at a glance.
- **Matrix**: entries by document type.
- **Search**: every document, filtered and sorted.
- **Browse**: curated ways in.
- **Checkout**: what your profile takes, and how to get the files.

Pick what you want, save the profile, and run one command to download it.

## How It Works

```text
 Extreme's sites                      this repo                               your library (any folder)
 ───────────────                      ─────────                               ─────────────────────────
 supportdocs.extremenetworks.com ─┐   config/        what to scan, types,      <your folders>/  the documents
 www.extremenetworks.com ─────────┴─> scanner/scan.py scan                      .docsync/profile.yaml
                                       ├─> results/catalog/   what the sites list       │
                                       ├─> results/reports/   what each scan found      │
                                       └─> index.html         the explorer ── profile ──┘
                                                          scanner/scan.py update --library <folder>
```

- **Scan.** The scanner reads the docs site whole and the main site's product, support and resource pages,
  and writes what they list to `results/catalog/`. It saves nothing but plain CSV, YAML and Markdown, so
  every change is a readable diff. It records where documents are but never downloads them. Support pages
  that carry tables (release recommendations, compatibility, End of Sale, MTBF) are kept whole as
  **snapshots**.
- **Report.** Each scan writes `results/reports/<date>/`:
  - `report.md`: coverage, timing, To Check, changes and numbers.
  - `changes.yaml`: the same, row by row.
  - `notes.md`: facts a person checked in the snapshots. They carry forward to be re-checked at the next scan.
- **Explorer.** `index.html`, rebuilt by every scan from `scanner/template.html`.
- **Library.** Any folder with a profile in `.docsync/profile.yaml`. `update` downloads what the profile
  takes, locks each file by hash, and keeps it current. Re-published files replace the old copy (which is
  archived), and files that leave the profile are archived too. `check` verifies the files.

## Use It

Python 3 and `pip install -r requirements.txt`.

```bash
python scanner/scan.py update --library ~/docs/fabric --profile my-profile.yaml   # the first time: copies the profile in
python scanner/scan.py update --library ~/docs/fabric                             # later: new and re-published files
python scanner/scan.py update --library ~/docs/fabric --dry-run                   # what it would download
python scanner/scan.py check --library ~/docs/fabric [--remote]                   # files against the lock; --remote asks the servers
```

A profile names what to take. The explorer writes one, or start from the starters in `config/profiles/`:

```yaml
profile_version: 1
about: Fabric Engine and the switches I run it on
use: [fabric-engine]                    # starter profiles, folded in
filters:                                # a document is taken if any filter matches it
  - entries: [5520 Series]
    types: [Installation Guide, Datasheet]
  - entries: [Fabric Engine]
    types: [User Guide, Release Notes]
    releases: [latest-per-line, {newest: 3}]   # default: latest
snapshots: [main-site/software-release-recommendations-for-voss-vsp-8600]
skip: []                                # urls never to take
folders: "{entry}"                      # or {type}, {release}, {profile}, combined with /
names: title                            # or original (the file's own name)
replaced: archive                       # a re-published file's old copy: archive | keep | delete
dropped: archive                        # a file that left the profile: archive | keep | delete
details: off                            # on: read each PDF's pages, revision and outline into .docsync/details.yaml
```

The rules for `releases` can be combined:
- **Position rules** work for every product, each by its own numbering: `latest`, `latest-per-major`,
  `latest-per-line`, `first-per-line`, `{newest: N}` release lines, and `all`.
- **Release numbers** (`{from: "9.2", to: "9.4"}`, or exact releases like `"9.4.1.0"`) belong to one
  product's numbering.

A library's tool folder, `.docsync/`, holds:

| File | Holds | Written by |
|---|---|---|
| `profile.yaml` | what the library takes | you, or the explorer |
| `lock.yaml` | every file: path, source, SHA-256, size, ETag, fetch date, earlier versions | `update` |
| `history.md` | what each update brought, newest first | `update` |
| `details.yaml` | per file: pages, revision, part number, outline (with `details: on`) | `update` |
| `archive/<date>/` | old copies of replaced and dropped files | `update` |

## Keep It Current

`config/sites.yaml` sets `rescan_after_days` (30). A scheduled job runs `scan --if-due`. After a scan:

1. Read the new `results/reports/<date>/report.md`. Work through **To Check**. Re-confirm the notes that
   carried forward in `notes.md`, then change their first line to "*Checked at this scan.*"
2. Commit everything together as "Scan <date>", and tag it `scan-<date>`. The next scan compares itself
   with this commit.

```bash
python scanner/scan.py scan [--if-due] [--only docs-site|main-site]   # about an hour; see scanner/NOTES.md
python scanner/scan.py due                                            # is a scan due? (exit 0 yes, 1 no)
python scanner/scan.py refresh                                        # rebuild report.md, Last Scan and index.html
python scanner/scan.py compare scan-2026-09-29 scan-2026-10-29        # what changed between two scans
python -m unittest discover scanner/tests
```

A scan stops without writing anything in two cases: it finds far fewer pages than the last scan, or many
pages fail to load. That usually means the site was throttling, so retry later. Pass `--allow-shrink` only
if the site really shrank.

## What Is Where

| Path | Holds |
|---|---|
| `index.html` | the explorer (generated) |
| `config/sites.yaml` | which sites are scanned, which parts, what isn't read, how often |
| `config/types.yaml` | document types, their value, and the title rules that recognise them |
| `config/profiles/` | starter profiles |
| `config/main-site-entries.yaml` | main-site product names paired with docs-site entries (so a datasheet belongs to its entry) |
| `config/compatibility.yaml` | which support tables say which hardware runs which software |
| `results/catalog/` | the catalog (generated): see below |
| `results/reports/<date>/` | each scan's report, changes and notes |
| `scanner/scan.py` | the scanner and the library tool; `docprofile.py` reads a PDF's details |
| `scanner/template.html` | the explorer's source |
| `scanner/NOTES.md` | how each site is built and read, and lessons from running scans |
| `scanner/EXPLORER.md` | what the explorer must do, for anyone changing it |
| `TODO.md` | open work |
| `LICENSE` | MIT for the code; the terms for the collected data |

**The catalog.** Most CSVs are *ledgers*: every row ever seen stays, with `first_seen` and `last_seen`.
The rows with the newest `last_seen` are what the site lists now.

| File | One row per |
|---|---|
| `docs-site/pages.csv` | docs-site page: heading, entry, role (`entry`, `release`, `orphan`), latest, release |
| `docs-site/listings.csv` | document listed on a docs-site page: title, release, date, format, via, url |
| `docs-site/release-notes.csv` | release note in the release-notes archive |
| `main-site/pages.csv`, `listings.csv`, `datasheets.csv` | in-scope main-site page; link on it; datasheet link |
| `documents.csv` | unique file either site lists; for an HTML guide, where it redirects (a new redirect means re-published) |
| `snapshots.csv`, `<site>/snapshots/` | a support page kept whole: `<name>.md`, and one CSV per table in `<name>/` |
| `<site>/health.csv` | what the parser may have missed: stray links, failed pages, orphans, lost datasheets |
| `last-scan.yaml` | when each site was scanned, its counts, and the timing of each step |

**Terms.**

- An **entry** is an item in the docs site's index (a product, an operating system, a series), grouped
  under a **heading**.
- **Latest** is an entry's newest release line: every release page with the newest major.minor. It means
  most recently published, not recommended. Extreme's recommendations are in the snapshots, and in each
  report's notes.
- **Format** is what a file is (pdf, zip, xlsx, api, video, page). **Via** is how it is reached:
  - `direct`
  - `html_guide`: a small site for one guide, with its PDF inside, which `update` fetches.
  - `content_hub`: the main site's file store.
